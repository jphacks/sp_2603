# フロントエンド設計

[docs/new-concept.md](new-concept.md) に合わせた、フロント (`apps/web`) の設計案です。API は [docs/design-backend.md](design-backend.md) に従います。見た目はデザイナーの案を待っているので、ここでは画面の動きとデータの流れだけを決めます。決まっていないことは最後の「未決事項」にまとめています。

## 今の実装から変えること

| 何を | どう変える |
| --- | --- |
| ステータス設定のポップアップ (`add-task-dialog.tsx`) | 下から伸びるタスク編集画面 (shadcn/ui の Drawer) に置き換える |
| タスクの追加 | 気球ではなくプールにブロックとして作る。気球へはドラッグ&ドロップで乗せる |
| タスクを消す | ブロックの右の × ボタンで 1 つずつ消す。プールのブロックも、乗っているブロックも消せる |
| 落としたタスクの履歴 | なくす。`GET /api/me/history` と乗せ直しの API を使わない |
| 経過時間による遠近 (`lib/balloon-distance.ts`) | なくし、`isAway` が `true` の人の気球とアイコンをグレースケールにする |
| 気球の見た目 | 大きさは全員同じにし、忙しさに応じて籠を大きくする |
| モーションセンサーの許可 | 小さなボタンではなく、ルームに入ったら許可を求めるダイアログを開く |
| ルームの画面のメニュー | ログアウト、ルームの変更、今のルーム ID の表示を足す |

ログイン画面とルーム入室画面のデザインの変更は、別のエンジニアが担当しているので、この文書では扱いません。

## 方針

- モバイルファーストで作る。PC のレスポンシブ対応は深く作り込まない。
- 忙しさ、離れているかどうか、合計 100% の制限はサーバーが計算した値を使う。フロントで計算し直さず、応答を待たずに画面を先に動かすこともしない。
- 揺れが強いかどうかの判定だけはフロントで行う。サーバーは呼ばれたらタスクを落とす。
- 気球の状態は、空の画面でもタスク編集画面でも同じものを見せる。どちらも同じキャッシュ (`GET /api/me/tasks` と `GET /api/rooms/{roomId}`) から描く。
- API は `@fllooat/api-client` が生成した hooks で呼ぶ。`fetch` を直接書かない。
- デザインが来るまでの見た目は仮置きにして、コードに `TODO: デザインが来たら見た目を差し替える` と書いておく。

## ライブラリ

| 用途 | ライブラリ | メモ |
| --- | --- | --- |
| ルーティング | TanStack Router (ファイルベース) | 雛形から使っている |
| データ取得 | TanStack Query + `@fllooat/api-client` | 雛形から使っている |
| スタイル | Tailwind CSS v4 | |
| UI の部品 | shadcn/ui (Radix ベース、Nova プリセット) | `pnpm --filter @fllooat/web exec shadcn add <名前>` で `src/components/ui/` に追加する |
| タスク編集画面 | shadcn/ui の Drawer (中身は vaul) | `shadcn add drawer` で入れる。下から出す |
| アニメーション | `motion` (旧 Framer Motion) | `import { motion } from "motion/react"`。気球の浮き沈み、ふわふわ、気球を揺らすドラッグ、ブロックのドラッグ&ドロップに使う |
| 横に並べるスクロール | `embla-carousel-react` | 環状のループと、人数が少ないときにスクロールを止める機能を使う。見た目は持たない |
| アイコン | `lucide-react` | shadcn/ui といっしょに入る |

ドラッグ&ドロップは `motion` の `drag` で作ります。dnd-kit などのライブラリは足りなかったときに検討し、入れる前にチームに相談します。

## フォント

GenInterfaceJP を使います。フォントファイルは `apps/web/public/fonts/GenInterfaceJP/` に置き、`src/index.css` に `@font-face` を書きます。Tailwind の `font-sans` は `"GenInterfaceJP", system-ui, sans-serif` にするので、ファイルを置く前はシステムのフォントで表示されます。

フォントを置いたら、[docs/third-party-licenses.md](third-party-licenses.md) の手順で `THIRD_PARTY_LICENSES.md` にライセンスを記録します。

## 画面とルーティング

| パス | ファイル | 画面 |
| --- | --- | --- |
| `/login` | `routes/login.tsx` | Google と GitHub のログイン |
| `/` | `routes/index.tsx` | 表示はない。ログインしていなければ `/login`、`GET /api/me` の `roomId` があれば `/rooms/$roomId`、なければ `/join` へ移る |
| `/join` | `routes/_authed/join.tsx` | 6 桁のルーム ID の入力と、ルームの新規作成 |
| `/rooms/$roomId` | `routes/_authed/rooms/$roomId.tsx` | 空の画面。タスク編集画面は Drawer で、気球の詳細はポップアップで開く |

`_authed` の下はログイン必須で、ログインしていなければ `/login` に送り、ログイン後に元の URL へ戻します。

`/rooms/$roomId` は次の場合に `/join?roomId=<その ID>` へ戻します。入力欄に ID が入った状態で開くので、ルームの URL を送るだけで仲間を招待できます。

- `roomId` が 6 桁の数字でない (このときは `roomId` を付けずに戻す)
- `GET /api/rooms/{roomId}` が 403 (`NOT_ROOM_MEMBER`) を返した。ほかの端末で別のルームに移ったときもこれに当たる
- `GET /api/rooms/{roomId}` が 404 (`ROOM_NOT_FOUND`) を返した (このときも `roomId` を付けない)

### `/join`

- `roomId` の検索パラメータがあれば、入力欄に入れておく。
- すでにルームに入っている人が開いたときは、「今のルームに戻る」ボタンを出す。
- ルームに入っている人が新しく作るか別の ID で入るときは、「今のルームから抜けます」と確認してから API を呼ぶ。

## データの取り方

### 画面と API の対応

| 画面 | 使う API |
| --- | --- |
| `/` | `GET /api/me` |
| `/join` | `GET /api/me` (今のルーム)、`POST /api/rooms` (作成)、`POST /api/rooms/{roomId}/members` (入室) |
| 空の画面 | `GET /api/rooms/{roomId}` |
| 気球の詳細 | `GET /api/rooms/{roomId}/members/{userId}` |
| タスク編集画面 | `GET /api/me/tasks`、`POST /api/me/tasks` (プールに作る)、`POST /api/me/tasks/{taskId}/load` (乗せる)、`DELETE /api/me/tasks/{taskId}` (消す) |
| 揺らして落とす | `POST /api/me/tasks/drop` |

### ポーリングと取り直し

- 空の画面は `GET /api/rooms/{roomId}` を `refetchInterval` で 3 秒ごとに取り直す。画面が裏に回っている間は止まる (TanStack Query の既定の動き)。サーバーはこの取得で「最後に画面を開いていた時刻」を更新するので、止まっている間は離れている扱いに近づく。
- 気球の詳細は、ポップアップを開いている間だけ同じ 3 秒の `refetchInterval` を付ける。閉じたら止める。
- タスクを作る、乗せる、消す、落とす API は、変えた後の自分の状態 (`MyStatus`) を返す。`hooks/use-apply-my-status.ts` が、応答を `GET /api/me/tasks` のキャッシュに `setQueryData` で入れ、ルームのキャッシュの自分の `busy` も書き換えてから、ルームの情報を `invalidateQueries` で取り直す。履歴の取り直しはなくす。
- ルームの情報が届くまでの一瞬、自分の気球だけを `MyStatus.busy` の高さに先に動かす。揺らした直後に気球がすぐ浮くのはデモの見せ場なので、ここは待たせない。タスク編集画面を開いたまま落としても、閉じたときには裏の気球がもう新しい高さにいる。

### エラーの扱い

API はエラーを `{ code, message, details }` の形で返します。フロントは `@fllooat/api-client` の `isApiError(error, code)` で `code` を見て分岐し、`message` は画面に出しません。

| `code` | フロントの動き |
| --- | --- |
| `UNAUTHORIZED` | `/login` へ送る。どの API で起きても同じなので、`QueryClient` の `QueryCache` と `MutationCache` の `onError` でまとめて扱う |
| `NOT_ROOM_MEMBER`、`ROOM_NOT_FOUND` | `/join` へ戻す。入室のときの `ROOM_NOT_FOUND` は「ルームが見つかりません」と出す |
| `MEMBER_NOT_FOUND` | 詳細のポップアップを閉じる (その人がルームを抜けた) |
| `TASK_NOT_FOUND` | `GET /api/me/tasks` を取り直す (ほかの端末で乗せたか、消したか、落とした) |
| `WEIGHT_LIMIT_EXCEEDED` | 乗せるときだけ返る。ブロックをプールに戻し、「あと N% までしか乗せられません」と出す。N は `details.remaining` |
| `VALIDATION_ERROR` | 入力欄の下に出す |
| `RATE_LIMITED` | 「少し待ってからもう一度試してください」と出す |
| `ROOM_ID_EXHAUSTED` | 「もう一度試してください」と出す |

## 空の画面

自分とほかの人の気球が並ぶ画面です。操作は横スクロールと、自分の気球を揺らすことだけにします。

### 気球の並び

旧コンセプトのとおり、1 画面に気球を 3 個並べ、自分を中心に置きます。

- `GET /api/rooms/{roomId}` の `members` は自分を含めて入室順に並んでいる。`isMe` の人を先頭にして回し、`[自分, 自分の次に入った人, ..., 自分の前に入った人]` の環状のリストを作る。自分の右隣が入室順で自分の次の人、左隣が自分の前の人になる。
- embla の `loop` で左右にスクロールでき、端まで行くと一周して自分に戻る。
- 自分を含めて 3 人以下のときは、スクロールを止めて自分を中心に固定する。2 人のときは、相手を自分の右に出す。
- embla の `loop` は、スライドの合計の幅が足りないと効かずに端で止まる。1 画面に 3 個だと 4、5 人のときに当たりやすいので、6 人未満のときはリストを 2 回つなげてスライドを増やす。同じ人が 2 つのスライドに出るが、一度に画面に入るのは 3 個なので重ならない。実際に何人から止まるかは、作ったときに確かめる。

### 気球の高さと籠

- 気球の高さは `busy` (0〜100) で決める。0% が一番上、100% が一番下。
- 高さが変わったときは `motion` のばねの動きで移す。止まっている間も、上下に少しふわふわさせる。
- 画面の左右どちらか (または両方) に目盛りを置き、今何 % か読めるようにする。
- 気球の大きさは全員同じにする。籠の大きさを `busy` から決める。`busy` から籠の大きさを出す処理は `lib/basket-size.ts` に関数として置き、数値はデザイナーと決める。
- 一番下 (100%) で籠が一番大きくなっても、画面の下の「タスクをのせる」のセクションに隠れないようにする。

### 離れている人

- `GET /api/rooms/{roomId}` の各メンバーの `isAway` が `true` なら、その人の気球とアイコンをグレースケールにする (Tailwind の `grayscale`)。大きさと濃さは変えない。
- 離れているかどうかはサーバーが計算するので、フロントは時刻を比べない。しきい値はサーバーの環境変数 `AWAY_THRESHOLD_MINUTES` で変わる。
- `lib/balloon-distance.ts` と、`Balloon` の `distance` は消す。

### 気球の詳細

他人の気球も自分の気球も、タップすると詳細のポップアップを開きます。名前、アイコン、忙しさ、乗っているタスクのタイトルと重さを出し、離れている人には「離れています」と出します。経過時間はもう API が返さないので出しません。

### メニュー

ログアウト、ルームの変更、今のルーム ID の表示を置きます。配置と見た目はデザイナーの案が届いてから決めます。

- ログアウトは `lib/auth-client.ts` の `signOut` を使う。キャッシュを丸ごと消してから `/` に移る (`components/user-menu.tsx` と同じ)。
- ルームの変更は `/join` へのリンクにする。抜けるときの確認は `/join` のものを使う。
- ルーム ID は 6 桁の数字をそのまま出す。

## タスク編集画面

旧コンセプトのステータス設定のポップアップを置き換えます。`components/task-editor-drawer.tsx` に作ります。

### 開き方と閉じ方

- 画面下の「タスクをのせる」ボタンがあるセクションを押すか上に引くと、そのセクションが上に伸びる形で開く。画面の 9 割ほどを覆い、背景は青のべた塗りにする。
- shadcn/ui の Drawer を `direction="bottom"` で使う。上部につまみを置き、つまみを下に引くと閉じる。X のモバイルアプリのアプリ内ブラウザーに近い動きにする。
- Drawer の `handleOnly` を付け、つまみ以外のドラッグでは閉じないようにする。中のブロックのドラッグ&ドロップとぶつからないようにするため。

### 画面の中身

- 上半分に自分の気球を大きく描く。乗っているタスクはブロックとして籠の中に並べる。
- 下半分がプール。気球にまだ乗せていないブロックを `MyStatus.pool` の順 (作った日時の新しい順) に並べる。
- ブロックにはタイトルと重さを出す。ブロックの大きさを重さで変えるかは、デザインの案しだい。
- この画面ではドラッグ&ドロップだけを受け付ける。横スクロールと、気球を揺らすドラッグはしない。スマホを振るとタスクは落ちる (「揺らして落とす」)。

### ブロックを作る

- プールの近くに作成の入力欄を置き、タイトルと重さを入れてプールに作る (`POST /api/me/tasks`)。
- 重さは 1% 刻みのスライダーで、1〜100。プールに作るときは合計 100% の判定がないので、上限は `remaining` に合わせない。
- タイトルの入力欄は、API に合わせて 30 文字で止める。

### 気球に乗せる

- プールのブロックを `motion` の `drag` でつかみ、気球の上で離すと `POST /api/me/tasks/{taskId}/load` を呼ぶ。気球の上かどうかは、離したときの指の位置が気球の要素の `getBoundingClientRect()` の中にあるかで決める。
- 気球の外で離したら、ブロックはプールの元の位置に戻る。
- 応答を待つ間、ブロックは気球の上に置いたままにする。成功したら、応答の `MyStatus` で籠の中に移す。`WEIGHT_LIMIT_EXCEEDED` ならプールに戻して残りの % を出す。
- 残りの % より重いブロックも、つかめるようにしておく。断るのはサーバーの 409 に任せる。

### 1 つずつ消す

- プールのブロックにも、籠の中のブロックにも、右に × ボタンを置く。押すと `DELETE /api/me/tasks/{taskId}` を呼び、そのタスクだけを消す。
- 終わったタスクだけを消し、終わっていないタスクは気球に残せる。旧コンセプトで履歴からの乗せ直しが担っていたことの一部を、これでまかなう。
- 確認のダイアログは出さない。ブロックは作り直せばよいので、押す手間を増やさない。
- タイトルや重さの編集は MVP では作らない。直したいときは消して作り直す。

## 揺らして落とす

### 判定

`lib/shake-detector.ts` の `createShakeDetector` が、左右の動きの値を受け取り、強い動きの向きが短い時間に何度も入れ替わったら揺れとみなします。スマホの振りと、気球のドラッグの両方で同じ判定を使います。

| 入力 | 使う値 | しきい値 | 回数と時間 |
| --- | --- | --- | --- |
| スマホを振る | `devicemotion` の加速度の x (m/s²) | 12 | 1 秒以内に 4 回、向きが入れ替わる |
| 気球をドラッグする | `motion` の `onDrag` の速度の x (px/s) | 600 | 1 秒以内に 4 回、向きが入れ替わる |

しきい値は仮の値です。実機で触って調整します。

### スマホの振り

`hooks/use-device-shake.ts` の `useDeviceShake` を使います。空の画面でもタスク編集画面でも効くように、ルームの画面で 1 回だけ呼びます。

- 端末によっては `acceleration` (重力を除いた値) が `null` になる。そのときは `accelerationIncludingGravity` の x を使う。左右に振る動きなら重力の影響は小さいので、しきい値は同じでよい。
- HTTPS でない場合とセンサーがない端末では `unsupported` になり、空の画面でのドラッグだけで落とす。

### モーションセンサーの許可

- iPhone の Safari は、タップの中で `DeviceMotionEvent.requestPermission()` を呼ばないと値が来ない。許可のダイアログを勝手には開けない。
- そこで、ルームに入ったときに `permission` が `prompt` なら、許可を求めるダイアログ (shadcn/ui の Dialog) を自動で開く。中のボタンを押したら `requestPermission` を呼ぶ。
- Android と PC は最初から `granted` なので、ダイアログは出さない。
- 許可されなかったときは閉じるだけにする。ドラッグでも揺らせると知らせる案内は作らない。

### ドラッグとスクロールの取り合い (空の画面)

- 揺らせるのは自分の気球だけにする。ほかの人の気球はタップで詳細を開くだけ。
- 気球本体を押さえてドラッグすると揺れる。背景をドラッグするとスクロールする。embla の `watchDrag` に関数を渡し、自分の気球の上で始まったドラッグでは `false` を返して、embla がスクロールしないようにする。
- 気球のドラッグは横方向だけにして、離すと元の位置に戻る。

### 揺れたあと

揺れを検出したら `POST /api/me/tasks/drop` を呼びます。乗っているタスクはすべて消え、プールには戻りません。プールのブロックは残ります。

- 乗っているタスクが 0 件のときは呼ばない。落とすものがなく、サーバーも最終更新をもう持たないため。
- 呼び出し中にもう一度揺れても、二重には呼ばない。
- 応答の扱いは「ポーリングと取り直し」のとおり。タスク編集画面を開いていれば、籠の中のブロックが落ちる動きを見せる。

## 開発と確認

- API がなくても `pnpm dev:mock` で画面を作れる。ログイン済みで始まるので、`/rooms/123456` を直接開けば空の画面を見られる。
- `GET /api/me` とルームのモックは `apps/web/src/mocks/room.ts` に手書きで、状態を持つ形で用意している。Orval のモックのままだと、`isMe: true` の人が 0 人や 2 人になり、ポーリングのたびに全員の `busy` が変わってしまうため。プール、乗せる、消す API と `isAway` も、このモックに足す。離れている人を 1 人以上入れておく。
- スマホの実機での確認は、Cloudflare Tunnel で HTTPS の URL を付けて行う。手順は [docs/development.md](development.md#スマホの実機で確かめる) にある。

## 作る順番

1. バックが API のスキーマを変えて `pnpm gen` したら、型エラーを直す。遠近を外して `isAway` に、履歴と乗せ直しを外す。手書きのモックも同じ PR で直す
2. 離れている人のグレースケールと、気球の詳細
3. モーションセンサーの許可のダイアログと、メニュー (見た目は仮置き)
4. タスク編集画面の骨組み: Drawer、プールへのブロックの作成、× で消す
5. ブロックのドラッグ&ドロップで気球に乗せる
6. 籠の大きさ
7. デザインの反映
8. 実機でしきい値を調整し、デモの流れを通して確かめる

## 未決事項

| 項目 | 案 | 理由 |
