# Fllooat コンセプト (旧)

## 概要

- プロダクト名: Fllooat
- 由来: Float (浮く) + Balloon (気球)
- ひとことで: 今どれくらい暇かを気球の高さで表し、同じルームの仲間と共有するサービス

気球が上にあるほど暇で、下にあるほど忙しい。タスクを乗せると沈み、気球を揺らしてタスクを落とすと浮き上がる。

## 誰の、どんな困りごとか

対象は学生です。ハッカソンやチーム開発の演習のように、数人が同じ目標に向かって作業している場面を想定しています。社会人の業務での利用は考えていません。

こうした場面では、「今この人に話しかけていいか」「手が空いている人は誰か」が見えにくい。タスクの種類はコーディングやデザインに限らないので、サークルや研究室など、ほかの集まりにも使えると考えています。

## 既存のサービスとの違い

Discord や Slack のステータスは、チャットやコミュニティの機能に付いているもので、そのサービスを使っている間の状態を表します。Fllooat は暇を共有すること自体が主な機能で、ステータスが中心にあります。将来は、各所に散らばったステータスを 1 か所にまとめる場所にしたいと考えています。

## MVP の目標

Hack Day のデモで、次の流れが実際に動くことを目標にします。

1. ログインして、ルームを作る。別の端末から 6 桁の ID を入れて同じルームに入る。
2. タスクを追加すると、自分の気球が沈む。ほかの端末の画面でも沈む。
3. スマホを振る (PC ならドラッグで揺らす) とタスクが落ちて、気球が浮き上がる。
4. 気球をタップすると、その人のタスクと最終更新からの経過時間が見える。

## MVP でやること

### ログイン

- Better Auth で Google と GitHub のログインを使う。
- アイコンとユーザー名は、最初にログインしたプロバイダのものを使う。編集はできない。

### ルーム

- ログインした後、ルームに入っていなければ「ID を入力してルームに入る」か「ルームを新規作成する」画面を出す。
- ルーム ID は 6 桁の数字。入力の手間と ID の数のバランスでこの長さにした。
- ID を知っていれば誰でも入れる。承認や試行回数の制限は MVP では作らない。
- 1 人が入れるルームは 1 つだけ。別のルームに入ると、前のルームからは抜ける。
- ルームの人数に上限は設けない。
- ほかの人の気球の動きは数秒ごとの再取得で反映する。

### ルームの画面の並び

- ホーム画面には気球を 3 個並べる。最初は自分の気球が中心にある。
- 自分を含めた全員を入室順に並べて輪にし、自分を起点に回したものを表示する。自分の右隣は自分の次に入った人、左隣は自分の前に入った人になる。全員が同じ輪を見るので、誰の画面でも隣り合う人は変わらない。左右にスクロールでき、端まで進むと一周して自分に戻る。
- 自分を含めて 3 人以下のときは、自分を中心に固定してスクロールできないようにする。2 人のときは、相手を自分の左右どちらかに出す。左右のバランスは多少崩れるが許容する。
- モバイルファーストで作り、PC のレスポンシブ対応は深く作り込まない。

### 気球の操作

- 気球本体を押さえてドラッグすると揺れる。背景をドラッグするとスクロールする。
- 揺らしてタスクを落とせるのは自分の気球だけ。ほかの人の気球はタップで詳細を開くだけ。

### タスクと気球の高さ

- タスクはタイトル、重さ、作成日を持つ。作成日が違えば、同じタイトルのタスクをいくつ作ってもよい。
- 重さは %。0% は完全に手が空いている状態、100% はタスクから手が離せない状態。1% 刻みのスライダーで設定する。
- 乗っているタスクの重さの合計が、その人の忙しさになる。合計は 100% を超えられず、残りの % までしか選べない。
- 気球の高さは忙しさで決まる。画面の左右どちらか (または両方) に目盛りを置き、今何 % か読めるようにする。
- 重りやタスクのタイトルは気球には描かない。重さは高さだけで伝わるため。

### ステータス設定画面

- ステータス設定ボタンを押すとポップアップで開き、タスクのタイトルと重さを入れて追加する。
- 過去に落としたタスクの一覧があり、そこから選んでもう一度乗せられる。乗せ直すときも、新規作成と同じスライダーで重さを変えられる。乗せ直したタスクは、作成日を乗せ直した日時で上書きする。

### タスクを落とす

- 気球が強めに揺れたら、乗っているタスクがすべて落ちる。軽く触れた程度では落ちない。
- 気球を揺らす方法は 2 つ。スマホを振るか、気球をマウスや指で押しながらドラッグして揺らす。PC やセンサーが使えない端末でも落とせる。
- 落としたタスクは「完了」か「いったん置いた」かを区別せず、手から離れたものとして履歴に入る。終わっていないタスクはもう一度乗せればよく、終わったタスクは放っておけば履歴の下のほうへ流れていく。
- 取り消しはない。間違えて落としたら、履歴から乗せ直す。

### 気球の詳細

- 気球をタップすると、その人のタスクのタイトルと重さ、最終更新からの経過時間が見える。
- 他人のタスクのタイトルは、この詳細でだけ見える。

### 経過時間による遠近

更新から時間が経った気球ほど、遠くにあるように小さく薄く描く。更新を忘れた人の情報を、そのまま信じないで済むようにするため。

| 最終更新から | 見た目 |
| --- | --- |
| 1 時間以内 | 標準の大きさで、一番濃い |
| 3 時間以内 | 少し小さく、少し薄い |
| 12 時間以内 | さらに小さく、薄い |
| 12 時間より前 | 一番小さく、一番薄い。これ以上は変えない |

境目の時刻はその段階に含めます。たとえば、ちょうど 1 時間前の更新は「1 時間以内」です。

## MVP でやらないこと

- 他人の気球を見た後のアクション (誘う、通知を送るなど)。暇か忙しいかがわかれば MVP としては十分とする
- 複数のルームへの同時参加
- ルームへの参加の承認、ID の総当たりへの対策
- アイコンとユーザー名の編集
- タスクを 1 つだけ落とす操作、落とした後の取り消し
- タスクの完了と保留の区別
- WebSocket などによるリアルタイム通信 (再取得で代わりにする)

## 実装の案

ここから下は、MVP の実装を始めるためのたたき台です。

### ルーティング

1 人 1 ルームなので、URL にユーザー ID を入れなくても、ログインしている人のルームが決まります。気球の詳細はページを分けずにポップアップにします。

| パス | 画面 |
| --- | --- |
| `/login` | ログイン |
| `/` | ルームに入っていれば `/rooms/$roomId` へ、入っていなければ `/join` へ移る |
| `/join` | ルーム ID の入力と、ルームの新規作成 |
| `/rooms/$roomId` | 気球の空。ステータス設定と気球の詳細はポップアップで開く |

自分が入っていないルームの URL を開いたときは、`/join` に戻して ID を入れてもらいます。

### テーブル

| テーブル | 主な列 | メモ |
| --- | --- | --- |
| `user` | Better Auth が作る | 名前とアイコンもここにある |
| `room` | `id` (6 桁の数字の文字列)、`created_by`、`created_at` | |
| `room_member` | `user_id` (主キー)、`room_id`、`joined_at`、`status_updated_at` | 1 人 1 ルームなので `user_id` を主キーにする。`status_updated_at` は遠近の計算に使う |
| `task` | `id`、`user_id`、`title`、`weight` (0〜100)、`state` (`on` か `dropped`)、`created_at`、`dropped_at` | 履歴は `state = dropped` を `dropped_at` の新しい順に並べる。乗せ直すときは `state` を `on` に戻し、`created_at` と `weight` を上書きする |

### ドメイン

本番は `https://fllooat.mfmf.moe` で公開する。Workers のカスタムドメインは cf CLI で設定する。本番の `BETTER_AUTH_URL` と、Google と GitHub の OAuth のコールバック URL も、このドメインに合わせて登録する。
